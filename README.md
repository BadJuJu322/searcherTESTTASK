# Document Search Service

Простой поисковик по текстам документов.

* **Python 3.12 + FastAPI** — асинхронный API
* **PostgreSQL** — хранилище документов (SQLAlchemy 2 async + asyncpg)
* **Elasticsearch 8** — поисковый индекс (анализатор `russian`, учитывает словоформы)
* **Docker Compose** — всё поднимается одной командой

## Быстрый старт

Нужны Docker и Docker Compose v2. На Elasticsearch понадобится около 1 ГБ свободной памяти.

```bash
# 1. Собрать и запустить БД, Elasticsearch и приложение
docker compose up -d --build

# 2. Дождаться, пока db и elasticsearch станут healthy (около 30–60 секунд)
docker compose ps

# 3. Загрузить тестовые данные (data/posts.csv, 1500 документов) в БД и индекс
docker compose exec app python -m app.load_data data/posts.csv
```

Готово:

* API — http://localhost:8000
* Swagger UI — http://localhost:8000/docs
* OpenAPI-схема — файл [`docs.json`](docs.json) (она же живьём на http://localhost:8000/openapi.json)

Остановить: `docker compose down` (данные сохранятся в томах). Остановить и стереть данные: `docker compose down -v`.

### Загрузка данных

```bash
docker compose exec app python -m app.load_data data/posts.csv           # загрузит, только если БД пустая
docker compose exec app python -m app.load_data data/posts.csv --reset   # сотрёт всё и загрузит заново
```

Скрипт проверяет весь файл до записи: при ошибке в CSV ничего не загрузится, а сообщение укажет номер записи.
Столбца `id` в CSV нет — идентификаторы выдаёт БД (1, 2, 3, …).

## API

| Метод | URL | Описание |
|---|---|---|
| `GET` | `/documents/search?q=<текст>` | Поиск. Возвращает до 20 документов со всеми полями, **сначала самые новые** |
| `DELETE` | `/documents/{id}` | Удаляет документ из БД и из индекса. `204` — удалён, `404` — не найден |

Полное описание, схемы и примеры ответов — в `docs.json` / Swagger UI.

### Примеры

```bash
# Поиск (слова запроса комбинируются через "И", учитываются словоформы)
curl -G "http://localhost:8000/documents/search" --data-urlencode "q=конкурс скин"
```

Формат ответа (пример, текст сокращён):

```json
[
  {
    "id": 2,
    "rubrics": ["VK-1603736028819866", "VK-95883495386", "VK-55347043459"],
    "text": "🎁 Конкурс на НОВЫЙ СКИН ‼️ ...",
    "created_date": "2019-05-31T17:18:42"
  }
]
```

```bash
# Удаление
curl -i -X DELETE "http://localhost:8000/documents/2"     # HTTP/1.1 204 No Content
curl -i -X DELETE "http://localhost:8000/documents/2"     # HTTP/1.1 404 Not Found
```

Пустой или отсутствующий `q`, `q` длиннее 500 символов, а также некорректный `id` дают `422`.
Если Elasticsearch недоступен, сервис отвечает `503`.

Особенности поиска: стоп-слова («и», «в», «на», «что» …) не учитываются, поэтому запрос, состоящий только из них, ничего не найдёт; служебные символы запроса не интерпретируются как синтаксис Elasticsearch (используется `match`, а не `query_string`).

```bash
docker compose run --rm tests                        # все тесты
docker compose run --rm tests pytest tests/unit      # только быстрые, без БД и Elasticsearch
```

* `tests/functional` — функциональные тесты: настоящие HTTP-запросы к приложению, настоящие PostgreSQL и Elasticsearch.
  Используются **отдельные** база `search_test` и индекс `documents_test`, поэтому рабочие данные не затрагиваются.
* `tests/unit` — разбор CSV, построение запроса и проверка, что `docs.json` совпадает с кодом.

## Принятые решения

**Как работает поиск.** В индексе, по условию, только `id` и `text` — даты там нет. Поэтому поиск в два шага:
Elasticsearch находит `id` подходящих документов → из PostgreSQL берутся полные документы, сортируются по
`created_date` (новые первыми) и обрезаются до 20. Благодаря этому в ответе всегда актуальные данные из БД.

**Какие документы считаются подходящими.** Запрос `match` с оператором `and`: в документе должны быть все слова
запроса. Результат сортируется по дате, а не по релевантности, поэтому режим «хотя бы одно слово» отдавал бы
много случайных совпадений. Анализатор `russian` приводит слова к основе: запрос «конкурс» найдёт «конкурсы».

**Удаление.** Сначала из БД (источник истины), затем из индекса. Если индекс в этот момент недоступен, клиент получит `503`,
но запись уже удалена из БД, а значит, в поиске не появится. Повторный `DELETE` дочистит индекс и вернёт `204`.
`404` возвращается, только если документа нет ни в БД, ни в индексе.

**Время.** `created_date` хранится и отдаётся «как в CSV», без часового пояса.

**Безопасность.** Пароли в `docker-compose.yml` — только для локального запуска. Elasticsearch работает без аутентификации, поэтому его порт `9200` опубликован только на `127.0.0.1`.

**Схема БД** создаётся при старте приложения (`create_all`) — для тестового задания этого достаточно.

## Ограничения и возможные улучшения

* Из индекса забирается не более 10 000 `id` на запрос (`SEARCH_MAX_CANDIDATES`, лимит `max_result_window` в Elasticsearch).
  Если совпадений больше, 20 новейших выбираются среди 10 000 самых релевантных. На 1500 документах это не проявляется.
  Для больших объёмов можно положить `created_date` в индекс и сортировать в Elasticsearch (по условию в индексе только `id` и `text`).
* Миграции (Alembic) вместо `create_all`.
* Нет авторизации и пагинации (по условию нужны только первые 20).
* Между БД и индексом нет распределённой транзакции; при сбоях расхождение лечится повторным вызовом (см. «Удаление»)
  или перезагрузкой данных с `--reset`.

## Если что-то не запускается

* **Elasticsearch сразу падает на Linux** — увеличьте лимит и перезапустите:
  `sudo sysctl -w vm.max_map_count=262144`.
* **Порт 8000 или 9200 занят** — измените левую часть в `ports` в `docker-compose.yml`.
* **Логи** — `docker compose logs -f app` (или `elasticsearch`, `db`).

## Запуск без Docker (для разработки)

Нужны запущенные PostgreSQL и Elasticsearch 8. Параметры подключения — в `.env` (образец: `.env.example`).

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
pytest
```

После изменения API перегенерируйте документацию: `python -m scripts.export_openapi`
(тест `test_docs_json_is_up_to_date` напомнит, если забыть).
